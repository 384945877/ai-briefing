OpenRouter 调用量：中国模型把“便宜好用”变成全球流量

2026-05-20 15:07 CST

OpenRouter 的调用量不是世界 AI 市场的总账本，但它能说明一件事：开发者真正在 API 里用什么。

证券时报转引每日经济新闻的测算显示，5 月 11 日至 5 月 17 日，OpenRouter 上中国 AI 大模型周调用量达到 7.693 万亿 Token，美国模型为 4.24 万亿 Token。中国模型已经连续三周超过美国，这一周大约是美国的 1.81 倍。

更有意思的是榜单里的具体名字。腾讯 Hy3 preview 周调用量 2.66 万亿 Token，环比涨 210%；DeepSeek-V4-Flash 2.06 万亿 Token，环比涨 86%；DeepSeek 旗下模型合计 4.25 万亿 Token，超过 Anthropic、Google，排在平台第一。

这不是一个“国产模型全面胜利”的结论。OpenRouter 是聚合平台，它的用户结构、价格策略、免费期、路由偏好都会影响调用量。比如 Hy3 preview 的暴涨，和限免期、接棒 free 版本都有关系。把这个数据直接外推成全球 AI 市占率，会过头。

但也不能把它当成噪音。过去外界讲中国模型，常说的是便宜、开源、追得快。便宜当然重要，可调用量连续几周上来，说明它不只是发布会上的低价标签，而是进入了开发者真实工作流。尤其是 agent 场景，模型调用会变得更碎、更频繁，单次推理便宜一点，堆到一周就是很大的差异。

这也是中国模型今年最现实的机会：不一定每个指标都要赢最强闭源模型，但可以在大量“够用、便宜、可路由”的任务里吃掉流量。代码补全、工具调用、批量总结、数据清洗、客服、自动化脚本，这些任务不总需要最贵模型。开发者会很诚实，谁稳定、便宜、延迟低，就先接谁。

真正要观察的是下一步。低价带来的调用量能不能沉淀成生态？开发者会不会为这些模型写适配层、做评测、建工具链？企业会不会把它从“备用模型”提到“默认模型”？如果只是靠补贴和免费期，调用量会很快回落；如果它开始进入 agent 框架和云平台默认选项，意义就不一样。

所以这条数据值得放进国内 AI 观察里。中国模型的竞争力正在从“模型发布时很热闹”，慢慢变成“海外开发者真的在调用”。这一步不性感，但很重要。AI 行业最后看的不是谁的 Demo 更会说话，而是谁能在每天几万亿 Token 的普通任务里活下来。

阿里云千问云：国内云厂商开始把 Agent 工具层摆到台前

2026-05-20 15:02 CST

阿里云今天在云峰会上发布“千问云”。科创板日报的口径里，它提供 Qwen、GLM、Kimi、DeepSeek、Wan、HappyHorse 等 150 多款模型 API，还把模型服务能力封装成 Skills 和 CLI 工具，方便 agent 调用模型和开发 AI 应用。

这条如果只看成“阿里又上了一个模型超市”，就有点浪费。真正值得看的，是阿里云把云能力往 agent 的使用方式里改。

过去一年，国内大模型竞争大多围着三个词转：能力、价格、开源。谁的模型更强，谁的 API 更便宜，谁的开源权重下载更多。但企业真的要用 agent，问题会马上变脏：它要查日志、读对象存储、起算力、连数据库、调用搜索、生成视频，还要知道哪些动作需要人确认，哪些数据不能出边界。

这正是云厂商最熟的地方。阿里云官方 Agent Skills 文档里有个细节：Skills 门户不是单纯放提示词，而是把特定任务的指令、脚本和参考资源封装成可复用能力包，并兼容 Cursor、Claude Code、Qwen Code、Codex、Gemini CLI、GitHub Copilot、OpenClaw 等客户端。换句话说，它想让 agent 不只是“会聊天”，而是能按规范碰云资源。

这个方向对国内 AI 很关键。中国模型这轮出海和增长，靠的是便宜、好用、开源快。但低价 API 很难长期成为护城河。模型一旦接进企业，客户要的不是“今天 token 又降价了”，而是这套东西能不能接进权限系统、账单系统、审计系统，出了问题能不能追到调用链。

千问云的意义可能就在这里：它把“模型服务”往“agent 工作台的底层供给”挪了一步。阿里云有模型，有算力，有存储、数据库、日志和安全产品。以前这些是开发者自己拼的云服务；现在它要把它们包装成 agent 可以发现、安装、调用的 Skills。

当然，这还不是胜利。Skills 能不能成为事实标准，要看开发者是不是愿意在真实项目里用，看企业是不是敢让 agent 调云资源，也看阿里云能不能把权限、计费、确认、回滚这些麻烦事做稳。agent 时代最难的地方，不是让模型说“我可以帮你操作云服务器”，而是让公司真的放心点确认。

所以我会把千问云放在国内 AI 基础设施的信号里看。它说明国内云厂商已经不满足于卖模型 API，开始争夺 agent 调用资源的入口。下一步要看的不是发布会上有多少模型，而是这些 Skills 有没有被真实开发者装进日常工作流。

Google DeepMind 与 Contextual AI：RAG 团队被买走的含义

2026-05-20 14:02 CST

Bloomberg 报道称，Google DeepMind 用约 1 亿美元许可协议，从 Contextual AI 招募 20 多名研究员，并获得其技术授权。Contextual AI 的联合创始人兼 CEO Douwe Kiela 也会加入。

这条看起来像一笔小型人才交易。放在 Google I/O 之后看，含义会更清楚：Google 刚把 Gemini Spark、Search AI Mode、Workspace agent、Chrome agent 串到一起，接下来最麻烦的环节，是企业数据怎么进模型，进来以后怎么少出错。

Contextual AI 做的就是这块。它从 2023 年开始强调 enterprise RAG 和 context layer，目标客户是需要可追溯、可控、能接私有知识库的公司。RAG 这几年听起来已经不新鲜，但企业里的硬活经常落在权限、版本、引用、更新、评估和幻觉责任上。模型回答错一句话，消费端只是尴尬；银行、律所、药企错一次，可能就是审计问题。

Google 自己当然有模型，也有 Workspace 和 Cloud。可企业落地不能停在把 Gemini 接到 Drive。不同公司有不同数据结构、审批流程、保留策略和合规要求。Contextual AI 这类团队的价值在于，他们长期盯着“企业知识怎么被模型可靠使用”这个窄问题。DeepMind 把人和技术一起拿进来，像是在给 Gemini Enterprise 补一块脏活能力。

这类交易方式也很有意思。结构是许可协议加团队迁移，并非完整收购。好处很明显：速度快，监管阻力小，买方拿到人和技术，卖方可能保留公司外壳或部分业务。过去一年，大厂用类似方式拿 AI 团队的动作变多，因为顶级研究员、可用产品经验、客户场景都比单纯代码更稀缺。

但这条也要谨慎看。报道来自匿名信源，Google 和 Contextual AI 还没正式公告；1 亿美元对 DeepMind 不大，对 Contextual AI 这类创业公司却可能改变公司命运。如果核心研究团队和 CEO 离开，留下的产品、客户和投资人怎么安排，还需要后续确认。

如果报道属实，这条新闻说明 Google 正在把 Gemini 的企业拼图补齐：模型、agent、办公入口、云算力之外，还需要一层能处理企业上下文的技术和人。消费端 AI 争的是入口，企业端 AI 争的常常是数据能不能被安全、准确、低摩擦地调用。Contextual AI 这类团队，刚好卡在这个缝里。

Karpathy 加入 Anthropic：明星流动背后的 pre-training 方法战

2026-05-20 13:02 CST

Karpathy 加入 Anthropic，最容易被写成一条 AI 圈明星流动新闻。但这条更有价值的地方，藏在岗位里：pre-training。

他自己在 X 上说，已经加入 Anthropic，接下来几年 frontier LLM 会很关键，自己会回到 R&D。TechCrunch 和 Axios 补了具体位置：本周开始，在 Nick Joseph 领导的 pre-training 团队工作。这个团队负责 Claude 核心能力的大规模训练，也就是模型成型前最贵、最慢、最难复盘的那一段。

Anthropic 需要 Karpathy，原因可能不止履历好看。他少见地同时懂三件事：大规模训练、工程落地、把复杂技术讲清楚。OpenAI 早期、Tesla Autopilot、Eureka Labs，这几段经历放在一起看，他横跨研究、工程和教学。他擅长把混乱系统拆成可训练、可观察、可教学的结构。

这对 Anthropic 很关键。过去一年 Claude 在编码、企业、金融场景里增长很快，但前沿模型的竞争仍要回到训练研究。算力当然重要，可同样重要的是每一次训练前怎么设假设、怎么挑数据、怎么设计评估、怎么判断一条路线该停还是该加钱。TechCrunch 提到一个细节：Karpathy 将参与建设一支用 Claude 加速 pre-training research 的团队。这个方向比“挖了一个大牛”更耐看。

大模型公司现在都在做一件很拧巴的事：用上一代模型帮自己造下一代模型。Claude 可以读论文、写实验代码、分析失败日志、整理训练异常，但研究员仍要知道哪些信号可靠、哪些只是模型写得顺。Karpathy 的价值可能就在这里。他既知道神经网络训练的脏活，也知道怎样把工具变成研究流程。

当然，别急着把这件事写成 Anthropic 短期爆发。Pre-training 的反馈周期很长，一个人加入到下一代 Claude 变强，中间隔着数据、算力、训练栈、评估和产品化。更现实的观察窗口，是 Anthropic 接下来会不会公开更多训练方法、研究工具，或者在 Claude Code / agent 体系里暴露更强的内部研究工作流。

AI 人才战过去常被写成薪酬和头衔的竞争。Karpathy 这条给出另一种信号：frontier lab 开始争夺能改造研究流程的人。谁能把模型变成研究员的放大器，谁就可能在同样算力下跑出更多有效实验。这件事短期不会有漂亮结果，但它离下一代模型的底层能力很近。

Gemini 3.5 Flash：Google 把“快模型”推上 agent 主舞台

2026-05-20 12:02 CST

Gemini 3.5 Flash 的名字还叫 Flash，但它的位置已经不太像过去的轻模型。

Google 官方这次直接 GA，没有 preview 过渡。它同时进入 Gemini app、Search AI Mode、Antigravity、Gemini API、Android Studio 和企业平台。官方给的几个数字也很硬：Terminal-Bench 2.1 76.2%，GDPval-AA 1656 Elo，MCP Atlas 83.6%，输出速度比其他 frontier models 快 4 倍。3.5 Pro 下个月来，Flash 先被推到前台。

这条发布会信息里，价格比榜单更有意思。Simon Willison 翻了开发者文档：3.5 Flash 是 1.50 美元 / 百万输入 token、9 美元 / 百万输出 token，约为 Gemini 3 Flash Preview 的 3 倍、3.1 Flash-Lite 的 6 倍，已经接近 Gemini 3.1 Pro 的 2 / 12 美元。一个叫 Flash 的模型，账单开始靠近 Pro。

过去 Flash 的心理位置很清楚：快、便宜、量大，适合做轻任务。现在 Google 把它拿来跑长链路 agent、编码、金融文档、子代理编排。模型能力被抬高后，开发者的成本表也会被重写。同样是“快模型”，如果一次任务要跑几十轮工具调用、生成大量中间结果，便宜感很快会消失。

Google 自己可以承受一部分成本。Search 和 Gemini app 是入口，免费用户带来使用习惯，AI Ultra 再承接高频和高权限需求。外部开发者的处境更微妙：他们需要 Flash 的速度和 agent 能力，又要面对更高单价、更长上下文、更大的输出量。agent 时代的账单不会只看每百万 token 单价，还要看任务完成前模型绕了多少路。

TechCrunch 也提到一个细节：3.5 Flash 可以自主运行数小时，但遇到决策点或权限问题会停下来问用户。这个边界很现实。Google 想让 Flash 成为执行引擎，可执行得越久，出错成本越高；问得越多，自动化体验越碎。3.5 Pro 未来负责规划，Flash 负责子任务，听起来像组织分工，落到产品里就是一次次权限、暂停和重试。

这条更适合看成模型定价的转折点。快模型已经不能自动等同于低成本模型。大厂把 agent 做深以后，Flash 这类“执行模型”会承担更多真实工作，也会把更多成本转给 API 客户。接下来开发者要测完整任务跑完以后的结果：账单和用户体验能不能同时站住。

Google I/O 2026：Gemini Spark 把 AI agent 接进 Gmail、Docs 和 Chrome

2026-05-20 11:06 CST

Google I/O 这次最重的产品动作，可能是 Gemini Spark：一个被放进 Gmail、Docs、Slides、Chrome 和 Gemini app 的 24/7 personal agent。

官方给 Spark 的定义很直接：它运行在 Gemini 3.5 和 Antigravity harness 上，可以在云端后台工作；先给 trusted testers，下周面向美国 Google AI Ultra 用户 beta。Google 还给 AI Ultra 增了 100 美元/月档位，把 Spark、Antigravity、更高用量和 YouTube Premium 打包进去。Spark 从第一天就按订阅层高频入口来设计。

Google 这次有一张别家公司很难复制的牌：邮箱、文档、浏览器、搜索、日历和 Android。一个 agent 要替人做事，难点很少停在“回答得好不好”。它需要知道你正在处理哪件事，能读到哪些资料，能调用哪些工具，动作完成后谁负责。Google 过去二十多年积累的产品网络，刚好卡在这些问题上。

Spark 的例子也很具体：整理信用卡账单里的订阅费、追踪孩子学校邮件、把会议材料和聊天记录整理成 Docs，再起草项目邮件。听起来不炫，但这些任务有共同点：资料散在多个 Google 产品里，用户懒得手动串起来。AI 的价值落在更琐碎的地方：少切五个窗口、少漏一封邮件、少重写一份文档。

麻烦也在这里。24/7 agent 越有用，权限越深。它要读邮件、看文件、跑浏览器、跨应用执行动作。Google 说高风险动作会先问用户，比如花钱、发邮件；这句话本身就说明产品边界还很紧。只要进入真实工作流，误发、误读、误订、误删都不再是聊天机器人里的小错误。

这条适合放进“AI agent 从聊天窗口进入默认工作入口”的脉络里看。模型能力仍重要，但 Google 的变量是分发和上下文：用户每天已经在 Gmail、Docs、Chrome、Search 里工作。Spark 能否成立，取决于它能不能把这些入口连成可靠的执行链，还要让用户愿意交出足够多的权限。

接下来更该看 beta 里的三件小事：它能独立跑多久；遇到模糊指令时会停下来问几次；企业管理员会给它开放哪些数据。agent 竞争大概不会只在谁回答更聪明上结束，很多胜负会藏在权限弹窗、审计日志和一封没发错的邮件里。

The Information：34 家头部 AI 创业公司年化收入近 800 亿美元

2026-05-18 11:53 CST

AI 应用层看起来热闹，账单却越来越集中。

The Information 的新数据很直白：34 家头部 AI 创业公司年化收入接近 800 亿美元，约每月 66 亿美元，六个月涨了 112%。但 Anthropic 和 OpenAI 两家公司合计拿走 89%。这组数来自媒体数据库和估算，不能当成审计财报读；可它足够说明一个方向：AI 创业的收入池在变大，收入控制权没有同步分散。

过去半年，市场爱讲“应用层爆发”。AI 客服、AI 销售、AI 编程、AI 搜索、AI 财务，每个场景都能长出一批公司。问题是，很多应用公司的收入里，有一部分会被模型调用、推理成本、云合约吃掉。客户付给应用公司，应用公司再把钱交给模型和算力供应商。营收数字很漂亮，毛利和议价权未必跟上。

这也解释了 Anthropic 和 OpenAI 的估值为何离谱得有点合理。它们收的已经不只是订阅费或 API 费，而是很多 AI 应用的“底层通行费”。企业采购也会把预算先给大模型平台：安全审查、权限管理、合规责任、供应商稳定性，这些东西对大客户比一个更好看的界面重要。

应用层当然还有机会，但机会会变窄。只包装模型能力的公司，会越来越像分销渠道；能留下来的公司，要么握住独占数据，要么嵌进客户流程，要么承担具体业务结果。比如做法务、财务、医疗、制造，不只是把答案吐出来，还要接住审批、责任、记录和交付。

这组数据最刺人的地方在于：AI 的商业化已经快到吓人；麻烦在钱流过来以后，谁能留住多少。接下来很多 AI 创业公司要回答的题，也从“有没有收入”变成“收入里有多少归自己”。

更大的影响在 agent 生态。很多第三方工具之前卖的是“把 Claude 订阅变成便宜执行引擎”。这条路被堵住后，工具本身要证明价值：能不能省 token、提高缓存命中、减少无效循环、把任务拆得更准。以后 agent 产品的竞争，不会只看接了哪个模型，还会看它有没有能力把一次任务跑得足够便宜。

我的判断偏冷：它短期伤开发者好感，长期会让 agent 市场少一点薅订阅漏洞，多一点真实成本核算。能留下来的，靠的不会只是调用 Claude 的壳；更要把模型调用、状态管理、权限、缓存和费用控制做成完整系统。
